
=======================================
     [Gym] Trainer Script Manual 
=======================================

※ Required Mod  
Cobblemon Trainer Battle Commands (TBCS)  
https://www.curseforge.com/minecraft/mc-mods/tbcs

----------------------------------------
1. Base state Settings
----------------------------------------
These settings define how the NPC behaves when idle.

- returnsHome: Determines whether the NPC returns to its home location when not engaged.  
- walkSpeed: Sets the NPC’s default walking speed.  
- moveType:  
  0 = stationary  
  1 = wandering  
  2 = fixed facing direction  
- maxHealth: Sets maximum NPC health.

---------------------------------------
2. time Settings
---------------------------------------
The time settings determine how timestamps and logs are handled.  
The configured time zone is used when recording events such as battles or contact exchanges with trainers.  
The default value is "Asia/Seoul", ensuring all logged times follow the Seoul local time.  
Using a consistent time zone helps maintain accurate chronological records.

---------------------------------------
3. ball Settings
---------------------------------------
The ball setting specifies which Poké Ball the NPC will display in their main hand during battle.  
This is mainly a visual element that enhances immersion when the trainer initiates a Pokémon battle.  
The default value is "cobblemon:poke_ball".

---------------------------------------
4. detect Settings
---------------------------------------
The detect system defines how the NPC senses nearby players.  
These settings control detection type, detection range, and responsiveness.

4-1. type  
This setting determines how the NPC detects players:
- 1: Interaction-based detection — NPC reacts only when interacted with.
- 2: Fixed-direction detection — NPC detects players entering a straight directional zone in front of them.
- 3: Circular detection — NPC detects players within a circular radius.  

4-2. interval  
Defines how often the NPC performs detection checks.  
Measured in ticks (20 ticks = 1 second).  
A lower number increases responsiveness; a higher number reduces performance load.  
Default: 20 ticks.

4-3. fixed  
Additional settings for fixed-direction detection:  
- angle: the NPC’s facing angle.  
- range: the length of the detection zone.  
- width: the width of the detection zone.  
These settings allow precise control over directional detection, useful for patrol-style trainers.

4-4. round  
Defines settings for circular detection:  
- range: radius in which the NPC can detect players.  
Default: 10 blocks.

---------------------------------------
5. start Settings
---------------------------------------
The start settings define how the battle begins once a player is detected and validated.

5-1-1. type  
Determines the method used to start the battle:
- 1: Immediate battle start.  
- 2: Auto-delay — displays a short GUI message before starting.  
- 3: Player confirmation — trainer asks if the player wants to battle.

Default: 2 (auto-delay).

5-1-2. delay  
Defines how long the system waits before starting the battle when using auto-delay mode.  
Default: 80 ticks.

5-1-3. denyMs  
Specifies the cooldown after a player rejects or cancels the battle.  
Default: 3000 ms (3 seconds).  
This prevents repeated challenge attempts and gives the player time to reposition.

---------------------------------------
6. gym Settings
---------------------------------------
The gym settings control the rules and behavior of Gym battles.  
This includes battle format, trainer data, requirements, and rewards.

6-1-1. battle  
Controls the battle rules:
- type: battle format (from TBCS)
  - 1: Single battle  
  - 2: Double battle  
  - 3: Multi battle  
  Default: 1  

- spec: name of the trainer JSON spec to load from the external folder.  
  This defines the trainer’s Pokémon team, moves, items, and behavior.

- maxItemUses: limits the number of times items can be used during the battle.  
  Default: 1

6-1-2. message  
Message shown in a GUI before the battle begins.

6-1-3. conditions  
Defines the requirements a player must meet before a battle can start.  
Possible condition types include:
- Item possession  
- Stored data values  
- Tags  
- Faction score requirements  

6-1-4. reward  
Defines rewards granted after winning the battle.  
Example:  
type: "xp", amount: 500 → awards 500 XP.

6-1-5. afterClearMsg  
Message shown when interacting with a Gym Leader who has already been defeated.  
Default: "You've already defeated me."

---------------------------------------
7. pos Settings
---------------------------------------
The pos settings manage optional teleportation before battles, placing the player and NPC in designated locations.

7-1-1. enable  
When set to true, both the player and NPC are teleported before the battle begins.  
Default: false.

7-1-2. tpNpc  
Coordinates for teleporting the NPC (x, y, z).

7-1-3. tpPlayer  
Coordinates for teleporting the player (x, y, z).

---------------------------------------
8. fe Settings (Trainer System)
---------------------------------------
These settings configure integration with the TBCS trainer system, allowing external trainer specs to be loaded.

8-1-1. apiId  
The required API ID for TBCS functionality.  
Default: "tbcs".  
Do not change this value.

8-1-2. externalDir  
Directory path where trainer JSON files are stored.  
Trainer specs placed in this folder are used for battles.

8-1-3. storeKey  
Key used to store the trainer ID inside the NPC's storeddata.  
Default: "trainer_attached_id".  
Changing this is not recommended.

---------------------------------------
9. sound Settings
---------------------------------------
Defines the audio cues used during the battle sequence.

9-1-1. pre  
Sound played before battle begins.  
Default: "minecraft:entity.ender_dragon_growl"

9-1-2. start  
Sound played at the moment the battle starts.  
Default: "minecraft:entity.player.levelup"
