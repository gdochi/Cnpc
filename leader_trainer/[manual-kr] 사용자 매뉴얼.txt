========================================
체육관 관장 스크립트 사용 매뉴얼
CustomNPCs 1.21.1 + RCT API + TBCS
========================================

스크립트 개요
- 첫 배틀(First Battle)
- 리매치(Round Rematch)
- 조건 검사(아이템, 태그, 발전과제, storeddata, 팩션)
- 보상 지급(아이템, XP, 발전과제, 팩션, 포켓몬)
- 기믹 실행(command, function)
- Trainer JSON 자동 attach/detach
- 외부 JSON 트레이너 스펙 실시간 반영

※ 필수 모드  
Cobblemon Trainer Battle Commands(TBCS)  
https://www.curseforge.com/minecraft/mc-mods/tbcs

----------------------------------------
1) FE – 트레이너 등록 설정
----------------------------------------
apiId        : Trainer API ID (기본 tbcs)  
               앱 ID가 변경되지 않는 이상 바꾸지 마세요.
externalDir  : 외부 JSON 폴더 경로(사용자 지정 가능)
debug        : 디버그 출력 여부(테스트용)
storeKey     : trainerId를 저장할 storeddata 키(변경 비권장)

----------------------------------------
2) CFG – 관장 설정 구조
----------------------------------------

[ state ]
returnsHome  : true/false – 배틀 후 원위치 복귀 여부
walkSpeed    : 이동 속도
moveType     : 0~2 – 서 있는 방식  
                0=정지, 1=걷기 허용, 2=바라보기 고정
maxHealth    : 관장 체력

[ sound.start ]
name, vol, pitch – 배틀 시작 직전 재생할 사운드

[ battle ]
type          : 1(single), 2(double), 3(multi)
maxItemUses   : 관장 최대 아이템 사용 수
ball          : NPC가 손에 들고 있을 볼 아이템

----------------------------------------
3) FIRST BATTLE 설정 (CFG.firstbattle)
----------------------------------------
spec        : 읽어올 trainer JSON 파일 이름 / 파일이름.json
message     : 배틀 시작 전 표시할 메시지
delay       : 배틀 시작 전 딜레이
maxItemUses : 배틀 중 NPC가 사용할 수 있는 최대 아이템 수

conditions  : 배틀 시작 조건 목록
 - type "item"        → 특정 아이템 요구
 - type "stored"      → 플레이어 storeddata 비교
 - type "advancement" → 특정 발전과제 필요
 - type "tag"         → 특정 태그 필요
 - type "faction"     → 특정 팩션 점수 필요

fail.msg    : 조건 불충족 시 출력할 메시지

reward      : 전투 승리 보상 목록  
 - item, xp, pokemon, advancement, faction, tag

gimmick     : 승리 후 실행될 효과  
 - type "command"
 - type "function" (스크립트 function() 실행)  
스크립트를 다룰 줄 알면 function을 통해 다양한 기믹을 추가할 수 있습니다.

----------------------------------------
4) REMATCH 설정 (CFG.rematch)
----------------------------------------
enabled : true/false – 리매치 기능 활성화 여부
rounds  : N단계 리매치 배열

각 round 설정 항목은 FIRST BATTLE과 동일하며 아래와 같이 구성됩니다:

spec        : 읽어올 trainer JSON 파일 이름 / 파일이름.json
message     : 배틀 시작 전 메시지
delay       : 배틀 시작 전 딜레이
maxItemUses : 배틀 중 NPC가 사용할 수 있는 최대 아이템 수

conditions  : 배틀 시작 조건 목록
 - item / stored / advancement / tag / faction

fail.msg    : 조건 불충족 시 출력할 메시지

reward      : 전투 승리 보상 목록  
 - item, xp, pokemon, advancement, faction, tag

gimmick     : 승리 후 실행될 효과  
 - command / function

플레이어 진행 상태는 storeddata["leaderData"]에 저장됩니다:
{
  NPC_UUID: { firstClear, rematchIdx, ts }
}

----------------------------------------
5) 배틀 위치 설정 (CFG.pos)
----------------------------------------
enable      : true/false
tpTrainer   : 관장 텔레포트 위치
tpPlayer    : 플레이어 텔레포트 위치

활성화 시 interact → timer 과정에서 자동 이동 처리합니다.

----------------------------------------
6) 트레이너 JSON 처리 흐름
----------------------------------------
interact 시:
 - 시작 조건 검사
 - 프리배틀 GUI 출력
 - 배틀 개시 타이머 시작

timer 시:
 - NPC/플레이어 위치 조정
 - faceEach로 서로 바라보게 설정
 - 외부 JSON을 임시 runtime 파일로 복사(applyTrainerRuntime)
 - trainerId를 부여하고 NPC에 attach
 - 사운드 재생
 - /tbcs battle 명령 실행

전투 종료(trigger id=1) 시:
 - 보상 지급
 - gimmick 실행
 - storeddata 갱신
 - rematchIdx 증가
 - NPC 상태 초기화

----------------------------------------
7) 조건 검사 함수
----------------------------------------
allConds() → 조건 배열이 모두 충족되는지 검사  
okCond()   → item, stored, advancement, tag, faction 검사

----------------------------------------
8) 보상·기믹 처리 함수
----------------------------------------
giveRewards() → item, xp, pokemon, faction, advancement, tag 지급  
runGimmick()  → command 또는 function 실행

----------------------------------------
9) 플레이어 기록 구조
----------------------------------------
leaderData = {
  NPC_UUID: {
    firstClear: true/false,
    rematchIdx: 숫자,
    ts: "YYYY-MM-DD HH:MM:SS"
  }
}

10) 전체 사용 흐름 요약
----------------------------------------
1. 플레이어가 NPC 우클릭  
2. 첫 배틀인지 리매치인지 판단  
3. 조건 충족 여부 검사  
4. 프리배틀 GUI 출력  
5. 딜레이 후 자동 배틀 시작(tbcs battle)  
6. 승리 시 보상·기믹 처리  
7. 리매치 단계 업데이트  

----------------------------------------
11) 외부 JSON 시스템 원리
----------------------------------------
- spec.json을 읽어 임시 runtime 파일 생성  
- trainerId로 등록 후 NPC에 attach  
- 배틀 종료 후 자동 detach  
- 임시 파일 삭제  
- 서버 재시작 없이 trainer 스펙 교체 가능  

----------------------------------------
12) 관리자용 LeaderData 관리 기능
----------------------------------------
플레이어들의 Gym Leader 진행 데이터(leaderData)를 확인·삭제할 수 있는
전용 관리자 도구입니다.
해당 기능은 check_data.js 스크립트를 플레이어 스크립트에 붙여넣으시면 됩니다.

▶ 관리자 전용 채팅 
   "!leader"  
   - 일반 플레이어는 사용 불가  
   - ADMINS 배열에 등록된 플레이어만 사용 가능  
     (예: ["Great_dochi","jerry"])

▶ 주요 기능  
1. 모든 플레이어 목록 표시  
2. 각 플레이어가 leaderData를 가지고 있는지 표시  
   - HAS = 데이터 존재  
   - NONE = 데이터 없음  
3. 버튼 클릭으로 특정 플레이어의 leaderData 즉시 삭제  
4. 삭제 성공/실패에 따라 사운드 출력  
   - 성공: 경험치 픽업 소리  
   - 실패: 모루 충돌 소리  
5. GUI 자동 새로고침
6. 추후 서버 완장 전용 gui를 만들 계획입니다. 그때 보완해서 합치겠습니다.

----------------------------------------
13) 문제 해결 가이드
----------------------------------------
▶ JSON을 읽지 못함  
  - externalDir 경로 확인  
  - spec 파일명과 실제 JSON 파일명 일치 확인  

▶ 배틀이 시작되지 않음  
  - conditions, fail 메시지 확인  
  - tbcs battle 명령 오류 여부 확인  

▶ 리매치가 동작하지 않음  
  - storeddata leaderData 확인  
  - rematch.enabled / rounds 배열 크기 점검
